# Concurrency and lifecycle mockups

These ImageGen mockups accompany the confirmed
[concurrency and lifecycle plan](../../CONCURRENCY_LIFECYCLE_PLAN.md). They are
behavioral design references, not implementation screenshots.

Every image was generated by editing the current VidStow Queue or Settings
screenshot. The prompts required the existing 160 px graphite sidebar, light
neutral canvas, restrained blue accent, typography, spacing, controls, and
flat desktop framing to remain unchanged.

| File | Behavior being validated |
| --- | --- |
| `ui-01-queue-overview.png` | Default concurrency 2, distinct running and slot counts, independent progress, and FIFO positions |
| `ui-02-transitional-states.png` | Pausing, Canceling, and Finalizing occupy slots; detached Cleaning up does not; Pause All settles asynchronously |
| `ui-03-outcomes.png` | Failed uses Retry, Canceled uses Download again, and destination issues use Action required |
| `ui-04-queue-settings-v2.png` | Limits remain 1–10/default 2, lowering drains, and restored work always returns paused without a toggle or auto-starting |
| `ui-05-quit-confirmation-v3.png` | Ordinary quit pauses and preserves; destructive quit is absent; no background/tray promise |
| `ui-06-recovery-required.png` | Invalid State fails closed, preserves evidence, disables mutation and cleanup, and exposes diagnostics only |
| `ui-07-destination-conflict.png` | Late collision never overwrites; a deterministic ` (2)` reservation is offered instead |

Review the behavior and copy against the plan before treating any image as an
implementation target. If a product decision changes, update the plan first
and regenerate only the affected mockup.

Superseded generations are retained only for provenance:

- `ui-04-queue-settings.png` predates the decision to remove the restoration
  toggle.
- `ui-05-quit-confirmation.png` has an incorrect safe waiting/paused count.
- `ui-05-quit-confirmation-v2.png` corrects that count but predates the decision
  to defer destructive quit.
